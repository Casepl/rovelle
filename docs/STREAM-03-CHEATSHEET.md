# Стрим 3: blob get

## Результат

```text
put file → hash → get file → cmp succeeds
tamper blob → get fails → old destination survives
```

## Хук для записи

> Что будет, если в хранилище изменится один байт? Обычное копирование молча
> отдаст битый файл. Сегодня я учу Rovelle находить подмену и не выпускать
> повреждённый артефакт. На C, которого я почти не помню.

## План эфира

### 00:00–00:05 — контекст

- Rovelle доставляет только изменившиеся части приложения без перезапуска пода.
- Сейчас строим самый нижний слой: content-addressed storage.
- `put` уже работает. Сегодня делаем безопасный `get`.

### 00:05–00:12 — показать исходную точку

```sh
./build/rovelle blob put /tmp/rovelle-store README.md
find /tmp/rovelle-store -type f
```

Нарисовать в Excalidraw:

```text
hash → objects/9b/e43...
```

### 00:12–00:22 — определить контракт

```c
rovelle_status_t rovelle_blob_get(
    const char *store_path,
    const char hash[ROVELLE_SHA256_HEX_SIZE],
    const char *destination_path
);
```

Решения вслух:

- принимаем только 64 символа `0-9a-f`;
- вводим `ROVELLE_CORRUPT`;
- пишем рядом с destination во временный файл;
- публикуем результат только через `rename()`.

### 00:22–01:05 — реализация

1. Валидация хеша.
2. Формирование пути blob.
3. Временный файл `<destination>.tmp-XXXXXX`.
4. Копирование через существующий `copy_stream()`.
5. `fflush`, `fsync`, `fclose`.
6. SHA-256 временной копии.
7. Сравнение хешей.
8. `rename()` или cleanup.
9. Команда `blob get` в CLI.

После каждого этапа проговаривать:

```text
Сейчас мне нужен ...
Я ожидаю ...
Проверяю это командой ...
Получилось ...
```

### 01:05–01:20 — демонстрация

1. `put`, затем `get`, затем `cmp`.
2. Повредить blob одним байтом.
3. Оставить в destination строку `working version`.
4. Запустить `get` ещё раз.
5. Показать `ROVELLE_CORRUPT`.
6. Показать, что `working version` сохранилась.

Этот кусок нужен для шортса. Перед демонстрацией сделать паузу и повторить хук.

### 01:20–01:30 — вывод

- Что защищает хеш.
- Зачем временный файл находится рядом с destination.
- Зачем нужен атомарный `rename()`.
- Следующий шаг: manifest, который собирает несколько blobs в один релиз.

## Если пришёл новый зритель

Короткое объяснение:

> Я пишу Rovelle, платформу доставки изменений без перезапуска приложения.
> Сейчас делаю хранилище, где адрес файла равен его SHA-256. Сегодня учу его
> безопасно выдавать файл и замечать повреждение.

Повторять контекст примерно раз в 25 минут и после каждого нового вопроса из
чата, которому без контекста трудно понять происходящее.

## Минимальный результат, если застрял

Сделать рабочий `get` без проверки повреждения. Затем отдельно добавить:

```text
copy to temp → hash temp → compare → rename
```

Стрим всё равно заканчивается демонстрацией одного завершённого шага.
