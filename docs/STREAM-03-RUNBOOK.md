# Rovelle Stream 03: проверка целостности blob

## Результат стрима

Сегодня реализуем команду:

```sh
./build/rovelle blob get <store> <hash> <destination>
```

К концу стрима должны работать два сценария:

```text
put → get → исходный и восстановленный файлы совпадают
```

```text
повреждаем blob → get возвращает ROVELLE_CORRUPT → рабочий файл не меняется
```

## Название стрима

> Пишу проверку целостности на C, которого не помню | Rovelle #3

## Хук для начала и шортса

> Можно ли доверять файлу только потому, что он лежит по правильному хешу?
> Сегодня я специально сломаю blob и напишу проверку его целостности. На C,
> которого я почти не помню.

Альтернативный вариант:

> Этот файл лежит по адресу, который равен его SHA-256. Но правильный путь ещё
> не гарантирует, что содержимое не повредилось. Сегодня я специально сломаю
> blob и научу Rovelle замечать это до того, как файл попадёт в приложение.

# План стрима

## 00:00–00:05. Объяснить, что строим

> Я пишу Rovelle. Это платформа, которая должна доставлять изменения приложения
> без перезапуска подов. Сейчас мы строим самый нижний слой: хранилище файлов по
> содержимому.
>
> На прошлом стриме мы сделали `blob put`. Сегодня сделаем `blob get` с
> проверкой целостности.

Сразу обозначить финальную демонстрацию:

> В конце я вручную поврежу объект. Rovelle должна обнаружить это и не заменить
> рабочий файл.

## 00:05–00:12. Напомнить прошлый стрим

Подготовить чистое хранилище:

```sh
rm -rf /tmp/rovelle-store
rm -f /tmp/source.txt /tmp/restored.txt

printf 'hello rovelle\n' > /tmp/source.txt
```

Пересобрать:

```sh
rbuild
```

Положить файл:

```sh
./build/rovelle blob put \
    /tmp/rovelle-store \
    /tmp/source.txt
```

Команда напечатает SHA-256. Показать созданный путь:

```sh
find /tmp/rovelle-store -type f
```

На экране получится примерно следующее:

```text
/tmp/rovelle-store/objects/9b/e43cdff7b69dff...
```

Объяснение:

```text
9b       первые 2 символа хеша
e43...   остальные 62 символа
```

Нарисовать в Excalidraw:

```text
source.txt
    ↓ SHA-256
9be43cd...
    ↓
objects/9b/e43cd...
```

Главная мысль:

> Адрес объекта определяется содержимым. Одинаковые файлы получают одинаковый
> адрес.

## 00:12–00:18. Сформулировать новую задачу

Новая команда:

```sh
./build/rovelle blob get \
    /tmp/rovelle-store \
    <hash> \
    /tmp/restored.txt
```

Она должна:

1. Проверить формат хеша.
2. Найти объект по хешу.
3. Скопировать его во временный файл.
4. Вычислить SHA-256 полученной копии.
5. Сравнить фактический и ожидаемый хеши.
6. Опубликовать файл через `rename()`, если хеши совпали.
7. Вернуть `ROVELLE_CORRUPT`, если они различаются.

Схема:

```text
blob
  ↓ copy
temporary file
  ↓ SHA-256
expected == actual?
  ├─ yes → rename → destination
  └─ no  → unlink → ROVELLE_CORRUPT
```

## 00:18–00:28. Добавить контракт

Сначала добавить статус:

```c
ROVELLE_CORRUPT
```

Потом публичную функцию:

```c
rovelle_status_t rovelle_blob_get(
    const char *store_path,
    const char hash[ROVELLE_SHA256_HEX_SIZE],
    const char *destination_path
);
```

После этого:

```sh
rbuild
```

Это первая контрольная точка. Пока собирается проект, посмотреть чат.

## 00:28–00:40. Проверить входной хеш

Написать:

```c
static int is_valid_hash(
    const char hash[ROVELLE_SHA256_HEX_SIZE]
);
```

Правила:

```text
длина ровно 64 символа
разрешены только 0-9 и a-f
```

Объяснение:

> Хеш приходит из CLI. Если просто вставить произвольную строку в путь,
> пользователь сможет передать точки, слеши или другой мусор.

Снова собрать:

```sh
rbuild
```

## 00:40–01:05. Реализовать получение blob

Последовательность:

1. Получить `blob_path` через существующий `format_blob_path()`.
2. Открыть объект через `fopen(blob_path, "rb")`.
3. Собрать шаблон `<destination>.tmp-XXXXXX`.
4. Создать временный файл через `mkstemp()`.
5. Превратить дескриптор в `FILE *` через `fdopen()`.
6. Вызвать существующий `copy_stream()`.
7. Выполнить `fflush()`, `fsync()` и `fclose()`.
8. Вычислить хеш временной копии.
9. Сравнить хеши через `strcmp()`.
10. Выполнить `rename()` или удалить временный файл.

После нескольких законченных шагов:

```sh
rbuild
```

Пока идёт сборка, посмотреть чат и кратко повторить контекст.

## 01:05–01:15. Добавить CLI

Распознать команду:


Аргументы:

```text
argv[3] store

argv[5] destination
```


# Финальная демонстрация

## Сценарий 1. Целый объект

Получить хеш:

```sh
HASH=$(./build/rovelle blob put \
    /tmp/rovelle-store \
    /tmp/source.txt)

echo "$HASH"
```

Забрать объект:

```sh
./build/rovelle blob get \
    /tmp/rovelle-store \
    "$HASH" \
    /tmp/restored.txt
```

Сравнить:

```sh
cmp /tmp/source.txt /tmp/restored.txt
```

Показать содержимое:

```sh
cat /tmp/restored.txt
```

## Сценарий 2. Повреждённый объект

Найти его путь:

```sh
OBJECT=$(find /tmp/rovelle-store/objects -type f | head -n 1)

echo "$OBJECT"
```

Повредить:

```sh
printf 'damaged content\n' > "$OBJECT"
```

Создать рабочий destination:

```sh
printf 'working version\n' > /tmp/restored.txt
```

Попытаться получить повреждённый объект:

```sh
./build/rovelle blob get \
    /tmp/rovelle-store \
    "$HASH" \
    /tmp/restored.txt
```

Ожидаемый результат:

```text
blob get failed: ROVELLE_CORRUPT
```

Проверить старый файл:

```sh
cat /tmp/restored.txt
```

Должно остаться:

```text
working version
```

# Финальная фраза для шортса

> Я изменил содержимое прямо внутри хранилища. Rovelle скопировала объект во
> временный файл, пересчитала SHA-256 и обнаружила несовпадение. Повреждённая
> копия удалена, а рабочая версия осталась на месте.

Структура шортса:

```text
0–5 секунд     хук
5–10 секунд    файл и его хеш
10–17 секунд   намеренно портим объект
17–25 секунд   запускаем blob get
25–32 секунды  ROVELLE_CORRUPT
32–40 секунд   рабочий файл остался целым
```
