# Стрим 4: manifest релиза

## Одна цель

```text
несколько blobs → проверенный manifest → SHA-256 ревизии
```

## Хук

> У меня уже есть файлы по хешам. Но набор случайных хешей ещё не является
> релизом. Сегодня я соберу manifest, изменю один файл из двух и покажу, почему
> второй не нужно доставлять заново.

## План

1. Показать проблему набора несвязанных blobs.
2. Зафиксировать формат `ROVELLE-MANIFEST-V1`.
3. Вынести `rovelle_hash_is_valid()`.
4. Добавить `rovelle_blob_verify()`.
5. Проверить безопасный логический путь.
6. Прочитать строки через `getline()`.
7. Проверить сортировку и каждый blob.
8. Сохранить manifest через `rovelle_blob_put()`.
9. Добавить `manifest publish` в CLI.
10. Показать v1, изменение одного файла и v2.

## Команда сборки

В начале эфира из корня проекта:

```sh
export PATH="$PWD/tools:$PATH"
rbuild
```

`rbuild` скрывает локальный путь и имя пользователя из вывода CMake.

## Проверки чата

Смотреть чат:

- после каждого `rbuild`;
- после схемы в Excalidraw;
- перед финальной демонстрацией;
- сразу после демонстрации.

## Если застрял

Минимальный результат эфира:

```text
manifest header
одна или несколько строк hash<TAB>path
проверка существования blobs
хеш manifest как revision
```

Строгую проверку всех вариантов пути можно закончить после эфира.

## Следующий шаг

```text
refs/current: revision-v1 → revision-v2
```

Переключение должно быть атомарным, а обе ревизии остаются неизменяемыми.
