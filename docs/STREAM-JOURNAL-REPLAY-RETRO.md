## Короткий итог

За эфир продолжительностью **1:08:11** замкнута первая вертикаль восстановления
Go control plane после перезапуска:

```text
revision-a записана
→ revision-b записана
→ новый процесс читает journal.jsonl
→ shop/production восстановлен с revision-b
```

`ReplayJournal()` читает события потоковым `json.Decoder`, различает нормальный
`io.EOF` и повреждённый JSON, применяет revision через существующий
`SetDesiredRevision()` и закрывает файл через `defer` на любом пути выхода.

## Что сработало

### Маленькие красно-зелёные checkpoint

Большая функция не писалась одним проходом. Работа шла через наблюдаемые
границы:

```text
контракт теста
→ красная заглушка ErrEmptyJournal
→ открыть файл
→ Decode одного события
→ цикл до EOF
→ восстановить revision-b
→ закрыть файл через defer
→ вернуть ошибку SetDesiredRevision
→ повреждённый JSON
```

Это позволило отдельно увидеть ложный зелёный тест: первая заглушка возвращала
заранее собранный `Environment`, хотя вообще не читала переданный файл.

### Новый механизм Go появился из реальной ошибки

`file.Close()` сначала находился после бесконечного `for`, но каждый выход из
цикла происходил через `return`. Cleanup был написан, однако выполнение до него
никогда не доходило. Перенос `defer file.Close()` сразу после успешного
`os.Open()` связал владение ресурсом и его освобождение в одном месте.

### Граница карточки сохранилась

На эфире не добавлялись HTTP, несколько environments, snapshots или
автоматическая запись из `SetDesiredRevision()`. Один новый учебный механизм
дал один видимый продуктовый результат.

## Что улучшить

### 1. Начинать с уже подготовленной карточки

Первые примерно пять минут ушли на запуск инструментов и подготовку карточки в
прямом эфире. Следующий эфир лучше начинать сразу с результата, текущего файла
и первого теста.

### 2. Не смешивать полный блок и текущий checkpoint

Фраза карточки про цикл и промежуточная просьба сделать один `Decode` выглядели
как противоречие. Полный алгоритм можно оставлять в карточке, но в живом
коучинге явно называть промежуточный шаг частью этого алгоритма.

### 3. Упростить отрицательный тест до одной цели

Во втором тесте табличная структура и цикл добавили больше механики, чем
требовал один повреждённый файл. Для одиночного отрицательного сценария
достаточен прямой setup, один вызов replay и проверка ненулевой ошибки.

## Кандидат для контента

Первый черновик Short был построен вокруг `defer`, но отклонён после просмотра:
он начинался с обрывка объяснения, содержал заметную паузу, а речь и экран
рассказывали разные части истории.

Новый кандидат использует одну законченную непрерывную реплику
`01:06:02.48–01:06:14.52` и одну последовательную мысль:

```text
процесс перезапустился
→ revision в памяти потеряна
→ ReplayJournal читает события JSONL
→ revision-b восстановлена
→ повреждённый JSON возвращает ошибку
```

Внутри выбранной реплики нет тишины длительностью от 0,8 секунды. Речь не
собрана из разрозненных фраз, а экранные карточки поддерживают именно replay,
о котором говорит владелец. Short остаётся кандидатом и не обязан публиковаться
только потому, что пакет подготовлен.

## Необязательные продолжения

- отдельный тест пустого журнала;
- проверка согласованности application/environment между событиями;
- оборванная последняя строка как отдельное продуктовое решение;
- несколько environments в одном журнале;
- автоматическая запись события при смене desired revision;
- HTTP API control plane.

Эти пункты не являются долгом текущего эфира. Решение о завершённости карточки
остаётся за владельцем.
