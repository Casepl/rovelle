# Rovelle: восстановить Environment из JSONL-журнала

## Результат эфира

После завершения процесса значение `DesiredRevision` больше не теряется:

```text
revision-a записана
→ revision-b записана
→ новый процесс читает journal.jsonl
→ shop/production восстановлен с revision-b
```

Сегодня появляется одна новая учебная функция:

```go
func ReplayJournal(path string) (Environment, error)
```

Она читает события по порядку и возвращает состояние после последней записи.
HTTP, база данных и автоматическая запись из `SetDesiredRevision()` в эту
карточку не входят.

**Время:** 45–75 минут. На 60-й минуте достаточно восстановить `revision-b` из
двух корректных событий и получить зелёный тест.

## Открывающий экран

```text
Результат: после перезапуска восстановлена revision-b
Где:      control-plane/journal_test.go → TestReplayJournal
Сначала:  записать красный тест с revision-a и revision-b
```

Первое действие занимает не больше десяти минут: запустить baseline и начать
только сценарий успешного восстановления. Остальные блоки открывать по мере
работы, а не читать всю карточку перед кодом.

## Зачем это Rovelle

Сейчас control plane уже умеет хранить выбор в памяти и дописывать его в
append-only JSONL:

```json
{"type":"revision_promoted","application":"shop","environment":"production","revision":"revision-a"}
{"type":"revision_promoted","application":"shop","environment":"production","revision":"revision-b"}
```

Но журнал пока только лежит на диске. После нового запуска кода никто не
превращает эти строки обратно в `Environment`. Сегодня замыкаем минимальную
вертикаль записи и восстановления.

## Граница задачи

Входит:

- открыть существующий JSONL-файл только для чтения;
- декодировать `RevisionPromoted` по одному событию;
- применить события строго в порядке строк;
- вернуть `Environment` с последней `DesiredRevision`;
- проверить две записи и ошибку повреждённой JSON-строки.

Не входит:

- несколько приложений и окружений в одном журнале;
- пропуск неизвестных типов событий;
- восстановление оборванной последней строки;
- слежение за растущим файлом;
- HTTP API, SQLite, снапшоты и compaction;
- автоматическая связь `SetDesiredRevision()` с записью события.

Для этой карточки журнал считается историей одного `Environment`. Поддержку
нескольких окружений и диспетчеризацию по `event.Type` не нужно проектировать
на эфире: вход содержит только события `revision_promoted` одного окружения.

## Контракт функции

```go
func ReplayJournal(path string) (Environment, error)
```

Вход:

- `path` — путь к уже существующему `journal.jsonl`.

Выход:

- `Environment.Application` и `Environment.Name` берутся из первого события;
- каждое следующее событие меняет `DesiredRevision` через существующий
  `SetDesiredRevision()`;
- после `revision-a`, затем `revision-b` возвращается `revision-b`;
- ошибка открытия, JSON decode или применения revision возвращается вызывающему
  коду;
- пустой журнал возвращает отдельную ошибку `ErrEmptyJournal`.

Конкретный пример на эфире только один:

```text
shop / production / revision-a
shop / production / revision-b
→ shop / production / revision-b
```

## 1. Зафиксировать сценарий восстановления — 10–15 минут

**Где:** `control-plane/journal_test.go`.

Подготовь путь через `t.TempDir()`. Дважды вызови уже готовую
`AppendRevisionPromoted()` — сначала для `revision-a`, затем для `revision-b`.
После этого тест должен вызвать будущую `ReplayJournal()` и проверить три поля:

```text
Application     == "shop"
Name            == "production"
DesiredRevision == "revision-b"
```

На этом шаге тест может не компилироваться: функции ещё нет. Это ожидаемое
красное состояние.

Проверка:

```sh
cd /Users/ssshcherbachenko/Rovelle
./tools/stream-go-test -run TestReplayJournal -v
```

**Успех:** ошибка указывает только на отсутствующую `ReplayJournal`.

**Дальше:** создать контракт и вернуть первое осмысленное состояние ошибки.

## 2. Объявить контракт и пустой журнал — 10 минут

**Где:** `control-plane/journal.go`.

Добавь `ErrEmptyJournal` и сигнатуру из карточки. Сначала функция может вернуть
нулевой `Environment` и эту ошибку. Не добавляй отдельные типы reader, store или
repository.

Понадобятся стандартные пакеты:

```text
errors
io
```

`io.EOF` здесь означает нормальный конец файла, а не повреждение. Но если EOF
наступил до первого события, это пустой журнал.

После объявления снова запусти целевой тест. Он уже должен компилироваться и
падать на ожидаемой `revision-b`, а не на отсутствии функции.

**Дальше:** открыть файл и декодировать первое событие.

## 3. Прочитать JSONL по одному событию — 15–20 минут

**Где:** `control-plane/journal.go`, `ReplayJournal()`.

Используй те же стандартные границы, что и при записи:

```text
os.Open(path)
→ json.NewDecoder(file)
→ Decode(&event)
→ закрыть file на любом пути выхода
```

Цикл должен различать три результата `Decode`:

1. событие прочитано — применить его;
2. получен `io.EOF` — чтение успешно закончено;
3. другая ошибка — прекратить replay и вернуть ошибку.

Не читай весь файл через `os.ReadFile()` и не дели строки вручную: новый
учебный механизм сегодня — потоковый `json.Decoder` и явная граница EOF.

После первого события заполни `Application` и `Name`. Revision применяй через
существующий `SetDesiredRevision()`, чтобы не дублировать проверку пустой строки.

Проверка:

```sh
cd /Users/ssshcherbachenko/Rovelle
gofmt -w control-plane/journal.go control-plane/journal_test.go
./tools/stream-go-test -run TestReplayJournal -v
```

**Успех:** из двух строк восстанавливается `revision-b`.

Можно сказать одну фразу:

> Теперь последняя revision восстанавливается из истории, а не остаётся только
> в памяти процесса.

**Дальше:** доказать, что повреждённая история не превращается в успешное
состояние.

## 4. Не скрывать повреждённую строку — 10–15 минут

Добавь второй subtest внутри `TestReplayJournal`: корректное первое событие и
повреждённая вторая JSON-строка.

Проверяй только, что ошибка не `nil`. Точный текст ошибки стандартной библиотеки
не закрепляй: он не является контрактом Rovelle.

Проверка:

```sh
cd /Users/ssshcherbachenko/Rovelle
./tools/stream-go-test -run TestReplayJournal -v
```

**Успех:** корректные две записи дают `revision-b`, повреждённая запись даёт
ошибку.

**Дальше:** полный финальный ритуал до остановки OBS.

## 5. Финальное доказательство — 5–10 минут

```sh

gofmt -w control-plane/journal.go control-plane/journal_test.go
./tools/stream-go-test -v
cd control-plane
go vet -trimpath ./...
```

Готово, если:

- существующие тесты записи журнала по-прежнему проходят;
- replay возвращает `shop / production / revision-b`;
- повреждённая JSON-строка возвращает ошибку;
- `go vet` завершается без сообщений;
- финальный зелёный запуск показан до остановки записи.

## Если к 60-й минуте не готов отрицательный сценарий

Остановиться на зелёном восстановлении `revision-b` из двух корректных событий.
Повреждённая строка — следующий короткий тест, а не причина расширять эфир до
90 минут.

## После эфира

Отдельными карточками остаются:

- несколько environments в одном журнале;
- оборванная последняя строка;
- автоматическая запись при смене desired revision;
- HTTP API для чтения и изменения состояния;
- snapshot и ускоренный replay длинной истории.

Ключ и статус задачи на доске MAIster в этой подготовке не подтверждены: перед
claim нужен актуальный URL или key открытой human-задачи.
