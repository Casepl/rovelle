# Research loop

Эта директория отделяет интересные чужие идеи от решений Rovelle. Статья,
доклад или сообщение сначала становятся материалом для обсуждения. Они не
изменяют архитектуру автоматически.

## Короткий процесс

```text
source
  -> claims
  -> questions
  -> Rovelle hypothesis
  -> experiment
  -> evidence
  -> decision or rejection
```

Для каждого материала создаётся одна карточка по `TEMPLATE.md` и одна строка в
`INDEX.md`.

## Статусы карточки

| Статус | Значение |
|---|---|
| `captured` | Материал сохранён, утверждения ещё не разобраны. |
| `analyzed` | Утверждения, ограничения и вопросы выделены. |
| `hypothesis` | Сформулирована проверяемая применимость к Rovelle. |
| `experiment-planned` | Описан ограниченный эксперимент и критерий результата. |
| `tested` | Есть локальные результаты и воспроизводимые evidence. |
| `promoted` | Вывод перенесён в DECISIONS, ADR, ARCHITECTURE или ROADMAP. |
| `rejected` | Гипотеза опровергнута или признана неприменимой. |
| `parked` | Материал полезен, но сейчас не относится к критическому пути. |

## Типы утверждений

- `reported-measurement` — число, сообщённое автором или поставщиком;
- `independent-measurement` — измерение, воспроизведённое независимым источником;
- `observation` — наблюдение без доказанной причинности;
- `design-principle` — предлагаемое архитектурное правило;
- `opinion` — оценка или прогноз;
- `local-evidence` — результат воспроизводимого эксперимента Rovelle.

Нужно сохранять контекст. Например, «cache hit выше 99%» означает только
результат конкретной системы при её нагрузке. Это не обещание Rovelle.

## Как мы обсуждаем новый материал

Когда в чат присылается ссылка, PDF, видео или чужой пост:

1. фиксируем автора и первичный источник;
2. отделяем слова автора источника от комментариев обозревателя;
3. разбиваем текст на отдельные claims;
4. указываем, какие claims измерены, а какие являются мнением;
5. ищем контрпримеры и скрытые предпосылки;
6. формулируем не решение, а гипотезу для Rovelle;
7. определяем самый дешёвый способ её проверить;
8. после обсуждения обновляем карточку.

Фразы «интересно», «похоже на Rovelle» и «можно использовать» не означают
promotion. Явное «принимаю это решение» переносит вывод в реестр решений без
дополнительного запроса подтверждения.

## Promotion в архитектуру

Перед переносом проверяем:

- какую проблему Rovelle решает идея;
- при каких нагрузках и ограничениях она нужна;
- есть ли более простой вариант;
- можно ли отложить решение без дорогой переделки;
- чем измеряется успех;
- какой источник или локальный эксперимент поддерживает решение.

После promotion карточка получает ссылку на `DECISIONS.md`, ADR,
`ARCHITECTURE.md` или задачу roadmap. Источник остаётся справочным материалом,
а принятое решение формулируется нашими словами и с нашими границами.

## Разделение файлов

```text
docs/research/
  INDEX.md                         очередь материалов
  TEMPLATE.md                      шаблон карточки
  2026-10-13-anthropic-scion.md    пример разбора статьи
  2026-10-14-ai-scale-ci.md        пример разбора доклада
```

Когда материалов станет много, их можно разделить по темам. До реальной
необходимости дополнительные каталоги и база данных не вводятся.
